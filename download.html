Voraussetzungen

  • Windows 10 oder 11
  • Docker Desktop (mit Compose)
  • Internetzugang für Installation und ersten Modell-Download. Fehlt Ollama, lädt der Installer es mit (ca. 1,5 GB).
  • Empfohlen: GPU mit ausreichend VRAM; ohne GPU läuft alles auf der CPU, deutlich langsamer.
  • Ein Zugangstoken (siehe unten)
Ollama wird nativ installiert, weil AMD-GPUs unter Windows nur so genutzt werden. In Docker-Containern läuft das Modell dort auf CPU und RAM.
Optional: Der Hardware-Agent (Windows-Dienst für echte CPU-/RAM-/GPU-Werte im Hardware-Dashboard) braucht Administratorrechte. Der Installer fragt danach.

Nach der Installation

  1. App öffnen: http://localhost:3000
  2. Beim ersten Aufruf folgt die Weiterleitung auf /setup. Dort legen Sie aus der Lizenzdatei das Unternehmen und den ersten Admin an.
  3. Beim ersten Start werden die KI-Modelle geladen, das dauert je nach Verbindung einige Minuten.

Der Installer legt das Verzeichnis ./sovereignmind an. Vorhandene .env, config.jsonl und models.json bleiben bei erneutem Ausführen unverändert.

Zugangstoken

Die Images sind nicht öffentlich. Für den Download brauchen Sie ein Token mit der Berechtigung read:packages. Es wird vom Anbieter bereitgestellt, hat nur Lesezugriff, läuft ab und kann jederzeit widerrufen werden. Token anfordern: siehe Kontakt. Nicht weitergeben und nicht in Repos oder Chats posten.

Sicherheitshinweis: docker login speichert das Token je nach System im Credential-Store oder unverschlüsselt in ~/.docker/config.json. Auf gemeinsam genutzten Rechnern nach der Installation docker logout ghcr.io ausführen.

Update, Stoppen, Datensicherung

Update: Installer erneut ausführen.

cd sovereignmind
docker compose down          # stoppen, Daten bleiben erhalten
docker compose down -v       # stoppen und alle Docker-Daten löschen (auch die Datenbank!)

Datensicherung (im Installationsverzeichnis, Stack läuft). Datenbank und Schlüsselordner gehören zusammen: ohne die Schlüssel sind gespeicherte Connector-Zugangsdaten unlesbar.

bash backup-db.sh                    # -> backups/<Zeitstempel>/
bash restore-db.sh backups/<Ordner>  # fragt vorher nach, überschreibt die Datenbank
# Windows: .\backup-db.ps1 bzw. .\restore-db.ps1 backups\<Ordner>

Den Ordner backups/ geschützt aufbewahren (enthält die Schlüssel). Dokumente sind darin nicht enthalten.
